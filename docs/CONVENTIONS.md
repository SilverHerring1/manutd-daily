# 编辑口径（不要每次重新讨论）

这些是已经定下来的规则。改之前先想清楚，别顺手改。
完整操作流程见 `WRITING-FLOW.md`；这份只管「什么算对」。

---

## 一、写作三件套

写日报只有三样东西要写：正文、标题、侧栏短评。三个各有一套硬规矩。

### 1. 正文（对应 football-writer）

一场 100–250 字，3–5 个 `<p>`，写进 `body_html`。

- **开头必须是具体的画面**：谁在第几分钟做了什么。不许「本场比赛」「双方展开激烈争夺」。
- **中段按分钟推进**，写动作不写评价。「第 66 分钟，他在禁区里推射，球进右下角。」
- **结尾停在一个事实上**：一个数字、一句原话、一个画面。不写「展现了韧性」「希望球队走出低谷」。
- 禁用词：顽强、精彩、可圈可点、值得一提、堪称、无疑是、这背后、这就是足球的魅力。
- 引语放 `quote` 字段（`zh` / `en` / `who` / `when`），不混进正文。

### 2. 标题（对应 football-headline）

**标准形态：`主队 比分 客队，事件`**

```
曼联 4-4 阿斯顿维拉，96分钟扳平
姆贝乌莫73分钟扳平，曼联 1-1 热刺
曼联 0-0 纽卡斯尔，全场零射正
```

| 规则 | 说明 |
|---|---|
| 分钟写全 | 「83分钟」「补时阶段」，**不写 `83'`、`90+6'`** |
| 必须有动词 | 禁止名词堆叠（`VAR 点球 曼联 2-0 雷丁` → `VAR 判点，曼联 2-0 雷丁`） |
| 不造词 | 用现成的：乌龙送礼、两度落后、梅开二度、补时扳平 |
| 进球数用术语 | 两个＝梅开二度/双响；三个＝帽子戏法；四个＝大四喜 |
| 一句一个成语 | 两个成语就是凑字 |
| 至少一个数字 | 比分、分钟、连胜场次 |
| 长度 10–18 字 | 超了砍修饰词，不砍信息 |
| 「曼联」看情况 | 比赛期带；转会/场外有人名就不带 |

**比分永远是主队在前**：`阿森纳 2-0 曼联`，不是 `曼联 0-2 阿森纳`。

### 3. 侧栏短评（对应 football-note）

`note.body`，30–60 字，一期一条。**不是摘要，是判断。**

两种结构，别贪多：

```
现象 + 判断：4-4 说明这支球队还有脾气，但第 18 名说明脾气换不来积分。
数字 + 代价：九场不胜结束在一场 3-2 里，代价是巴莱巴的腿筋和库尼亚的红牌。
```

- 不复述比分（标题和正文已经写了）
- 给判断不给情绪；允许带刺，但对事不对人
- 至少一个具体的东西：数字、人名、时间点
- 三种日期三种写法：**比赛日**挑别人没说的角度；**新闻日**给这件事定性（补救/赌博/姿态）；**赛季节点**可以拉长时间，但只拉一次
- 想用球迷热评：`note.title` 写「球迷热评」，带 `credit`（用户名，不是平台名）和 `url`；没有用户名就别用

## 二、时间与落位

- **全站用北京时间**。英国当地日期会差一天，跨天的场次在正文里标注「英国 X 月 X 日」。
- 一场比赛的归属：**踢完之后那一天**。晚上 22:00 开球 → 次日早报；凌晨 00:30 / 03:00 开球 → 当天早报。
- 当天傍晚的新闻 → **当天晚报**。
- `date` 格式 `YYYY-MM-DD`；`id` 必须是 `date-period`。
- 归档生成器用 **12:00 做分界**：北京时间 12 点前开球算当天早报，之后算次日早报。

### 什么内容单独一期

| 内容 | 处置 |
|---|---|
| 比赛 | 一场一期 |
| 转会 | **一条转会一条**，放官宣当天的早报或晚报 |
| 场外（下课、收购、风波、抗议） | 一件事一期，放发生当天的晚报 |
| 纪录 | 次日早报；只收历史级（队史首次、联赛纪录） |
| 杯赛夺冠回顾 | **夺冠才单独立一期**；没夺冠就并进那场比赛那一期 |
| 赛季总结 | 最后一轮之后单独一期 |

**合并原则**：同一天、同一个早/晚时段里的事，写成同一期的多个条目；不同天、或不同时段，才拆成两期。

## 三、期号与重排

- **期号跨赛季连续**：2018/19 第 1 期起，一路数到现在，不按赛季重数。
- **加完任何一期都要重排**，否则后面全错位：

```powershell
node tmp/renumber-season.mjs 2026-27   # 先本赛季
node tmp/renumber-global.mjs           # 再全球 9 季
# 再重算 data/seasons.json 的 count / first / last
```

- 重排之后重建归档页：`node scripts/gen-archive-issues.mjs --all --pages`
  - `--pages` 只写 `archive/*.html`，**不碰任何期次 JSON**；裸跑 `--all` 会把手写内容覆盖掉，禁止。
- 纯新闻期也占号，和比赛期一起按时间排序编号。

## 四、视角

- **当天视角**，不用上帝视角。写 10 月 11 日的稿子，不知道后面九场不胜。
- 只写当天已经知道的事：当时的排名、当时的伤情、当时说过的话。
- 禁止跨期判断：

| ❌ 上帝视角 | ✅ 当天视角 |
|---|---|
| 从那到现在一共九场没赢 | 六轮 1 胜 3 平 2 负，第 13 |
| 此后一直没有回到一线队训练 | 上半场拉伤，被提前换下 |
| 这是九场不胜里最难看的一场 | 这是本赛季丢球最多的一场 |
| 他后来真的下课了 | 四十八小时内会有答案 |

判据：写这句话的时候，作者当时**能不能知道**。
例外：数据面板可以写「截至目前」。

## 五、来源分级

| 级别 | 用途 |
|---|---|
| 曼联官网 / 官方声明 / 发布会全文 | **事实基准**：比分、阵容、伤情、原话 |
| The Athletic · David Ornstein（DO） | **一线独家**：换帅、转会、合同谈到了哪一步。权威，但仍不等于官宣 |
| BBC / Sky / 曼晚 / 泰晤士 / The Athletic 其他记者 | 可信分析、独家 |
| 懂球帝 / 直播吧 / 虎扑 | 找线索、中文表述；多为转载，不直接用结论 |
| X（跟队记者、罗马诺） | 转会突发；**必须标「未证实」** |

- 信息等级要露在字面上：「曼联官方宣布」「据 The Athletic 的 David Ornstein 报道」「据《曼晚》《镜报》报道」「据跟队记者 XXX」「有消息称，尚未证实」。
- DO 和罗马诺的区别写在句子里：DO 偏「俱乐部在做什么」，罗马诺偏「交易到哪一步」；两人都没官宣，就不许写成「已完成」。
- 不写「据悉」「据了解」——谁说的都说不清。
- 每条带 `sources`，链接指向原文，不指向聚合页。
- 官方没发声的事，写「尚无官方声明」，不替它下结论。
- **转会期的离队条目必须带数据**：在曼联的出场数和进球数，口径标「联赛」或「各项赛事」。
- 轶事、经纪人转述、二手说法，必须注明出处性质（例：卡塞米罗「I will fix this」是**经纪人的说法**，本人没有公开讲过）。

## 六、配图

- **不硬凑（第一原则）**：配图是为了把事说清楚，不是任务清单。一条新闻配不出「就是这件事」的图，就让它空着——**无图是正常形态**。宁可一期只有头图，也不塞一张「看着有点像」的图。
- **相关才配**：文件名里要有这个人，或者本身就是这座球场/这个事件。判据是「盖住标题，读者还能看出这是哪件事吗」，不能就别配。
- **不是每条都要有图**：一期里两条有图、三条没图，没问题；反过来为了「都有图」去凑，才是问题。
- **有图就用（在满足上面两条的前提下）**：信源里有对得上的图——曼联官网声明配图、BBC/Sky 正文首图、懂球帝正文图、球员本人 IG/X 帖截图——就取来当该条 `image`，别浪费。
- **竖图不用**：人像裁成 16:9 就是一张贴脸大图，宁可不配。**但社媒截图例外**：story 是 9:16，两张拼成 1200×800（3:2）再放，或从顶部裁 3:4 换掉下半截。
- **找不到就不配**：不用别场图、别队图、同名的教堂/街道/军队照片凑数，也不要拿旧期的同主题图来充数。
- **不用 AI 图 / 合成图**：`懂球帝` 有些配图是 AI 生成的「签约照」，看着像真图，实际不是，不能当新闻配图（11-13 的 6649192 就是这种，弃用）。同理，不用「俱乐部徽章 + 人脸」拼出来的示意图当新闻图。
- 尺寸统一 960×540（或 1200×800 的 3:2）；`credit` 写来源（Wikimedia Commons / Getty / 曼联官网 / BBC / 懂球帝 / 球员社媒）。
- `hero` 是期次头图（「今日要点」左边），`image` 是条目配图。没有 `hero` 就是无图版式，页面不出现空框。
- 比赛头图：`node scripts/fetch-archive-images.mjs <season>`，取该场 `article.images[0]`；**别抓 `news.articles[*]`**（那是 ESPN 推荐位，图跟比赛无关）。
- 新闻期配图检索走维基共享资源，需要代理（见第九节），且必须按文件名过滤主体后使用。

## 七、归档机制

- 一场一期，`data/seasons/<season>/<date>-morning.json`，格式和主线一致。
- **抬头只写「曼联早报」**（跟日更一致），比赛写进条目标题。
- 归档期次另带 `season`、`archive: true`；`kind` 为 `match` / `news` / `summary`。
- **归档只写比分能证明的事**：进球时间线、场地、赛事、截至这一场的累计战绩。没有原话就不写引语，没有同源图就不配图。
- 判断不越界：累计战绩、赛季最大分差、第几次被零封，一律只算到这一场为止。
- 杯赛平局按赛制写：联赛杯「九十分钟打平，进入加时；互射点球的结果没有记录」；足总杯「按赛制需要重赛」。不猜结果。
- 球员名保留英文原文，队名、场地走 `scripts/teams-cn.json`。
- 归档期次挂的是**当时的积分榜**：`app.js` 用 `data/standings/<slug>.json` 把全季比分算到这一场为止，不是当季的实时榜。
- `archive/` 下的页面由生成器写，别手改；`data/archive/` 由 import 脚本写，生成器只读。

### 焦点战（★）

- 口径统一叫**焦点战**，不叫「名局」（2026-11-13 统一，代码和文档一起改）。
- 判据（满足任一条）：BIG6 内战（利物浦、曼城、阿森纳、切尔西、热刺、利兹）、杯赛淘汰或晋级的关键场、争冠/保级/换帅后的关键战、赛季最大比分差。
- 名单写在 `data/focus.json`，按赛季、按**比赛日期**索引；归档页在赛程表上给这一行标 ★，生成器读它时用的是 `focus` 映射，不需要另开字段。
- 加/删焦点战只改 `data/focus.json`，然后 `node scripts/gen-archive-issues.mjs --all --pages` 重建页面。

### 淘汰赛路径

- 赛季页顶部一条「淘汰赛路径」：**只画曼联这一条**，不铺整张对阵树。
- 每条赛事一行节点：轮次 → 对手和比分，**比分曼联在前**（客场也写 3-1）。
- 淘汰那一轮标红，赛事名旁挂结论（止步八强 / 点球出局 / 夺冠）；两回合合并写（`0-2 / 3-1`），晋级方式放备注。
- 轮次名来自 ESPN：`node scripts/build-rounds.mjs <season>`。
- **决赛赢了才叫「夺冠」**；点球/加时/重赛 archive 里没有，写进 `data/cup-results.json`。

### 欧战小组表

- 紧跟「淘汰赛路径」下面，只放曼联那一组，4 行，曼联行标红。
- `node scripts/fetch-group.mjs 2018-19 champions|europa` 抓数据；不写「小组第几出线」这种结论。

## 八、排版与组件

- 一页一个 `h1`。正文列宽 38em。字号只允许四档。
- 组件不写裸像素和裸颜色，一律走 CSS 变量。
- 主题跟内容走：早报白纸，晚报近黑，**不跟系统深色设置走**。
- 队徽一律 FM 25×18 PNG，页面按原尺寸显示。
- 积分榜 20 行、曼联行标红；归档期次不挂榜单。

## 九、工具、缓存与代理

| 用途 | 命令 |
|---|---|
| 抓比赛技术统计 | `node scripts/fetch-commentary.mjs <season>` |
| 抓比赛头图（ESPN） | `node scripts/fetch-archive-images.mjs <season>` |
| 生成/重建归档期次 | `node scripts/gen-archive-issues.mjs <season>`（`--all` 全季，`--dry` 只看汇总） |
| 只重建归档页 | `node scripts/gen-archive-issues.mjs --all --pages` |
| 重排某季期号 | `node tmp/renumber-season.mjs <season>` |
| 重排全球期号 | `node tmp/renumber-global.mjs` |
| 抓积分榜 | `node scripts/fetch-boards.mjs` |
| 抓欧战小组 | `node scripts/fetch-group.mjs <season> champions\|europa` |
| 抓淘汰赛轮次 | `node scripts/build-rounds.mjs <season>` |
| 检查体积 | `node scripts/check-size.mjs` |

**网络**：Node 不走系统代理，直连维基/BBC 会被挡（DNS 投毒）。

```powershell
$env:HTTPS_PROXY='http://127.0.0.1:7897'
$env:HTTP_PROXY='http://127.0.0.1:7897'
node --use-env-proxy 脚本.mjs
```

- 通：`en.wikipedia.org`、`commons.wikimedia.org`、ESPN API、manutd.com
- 不通：`ichef.bbci.co.uk`、`pbs.twimg.com`、`resources.premierleague.com`
- 维基会 429 限流：请求间隔 ≥1.5 秒，撞到就退避 20–30 秒

- **仓库根目录就是站点**，GitHub Pages 从这个分支根目录出页。没有 `_site`、没有 `publish.mjs`。

| 角色 | 路径 |
|---|---|
| 工作目录（改文件、跑脚本） | `D:\Documents\deepseek-harness\default-workspace\manutd-daily` |
| Git 仓库（GitHub Desktop 推送用） | `D:\Documents\GitHub\manutd-daily` |

- 改完同步到仓库副本（脚本按 md5 比对，只复制变化；也可以手动 robocopy）：

```powershell
node scripts/sync-desktop.mjs          # 默认同步到 D:\Documents\GitHub\manutd-daily
```

- 动了 `app.js` / `layout.css` / `index.html` → **把 `index.html` 里的 `app.js?v=N` 加一**，破缓存。
- GitHub Desktop：Current Repository 选 `manutd-daily` → Changes 核对 → Summary 一句话 → **Commit to main** → **Push origin**。
- Pages 构建 1–2 分钟，强刷 `Ctrl+Shift+R`。
- 本地预览：`python serve.py` 或 `启动.cmd`；线上 https://silverherring1.github.io/manutd-daily/
