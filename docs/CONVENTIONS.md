# 编辑口径（不要每次重新讨论）

这些是已经定下来的规则。改之前先想清楚，别顺手改。

## 时间

- **全站用北京时间**。英国当地日期会差一天，涉及跨天的场次在正文里标注「英国 X 月 X 日」。
- 一场比赛的归属：**踢完之后那一天**。晚上 22:00 开球 → 次日早报；凌晨 00:30 / 03:00 开球 → 当天早报。
- 当天傍晚的新闻 → **当天晚报**。
- 日期写进 JSON 的 `date`，格式 `YYYY-MM-DD`；`id` 必须是 `date-period`。
- 归档生成器用 **12:00 做分界**：北京时间 12 点前开球算当天早报，之后算次日早报。

## 归档

- 一场一期，`data/seasons/<season>/<date>-morning.json`，格式和主线 `data/*.json` 一样。
- **抬头只写「曼联早报」**（跟日更一致），比赛写进条目标题：`巴黎圣日耳曼 1-3 曼联：净胜 2 球`。
- **期号跨赛季顺延**：2018/19 第一篇是第 1 期，往后一直数下去，新赛季接着上一季的号往下排，不按赛季重数。抬头显示「第 42 期 · 2018/19 · 晨间版」。
- **主线也按赛季归档**：所有期次都在 `data/seasons/<赛季>/`，每季一个 `index.json`；`data/index.json` 只留元信息（name / as_of），不再存 `issues`。新期用 `node scripts/new-issue.mjs` 写，脚本会按日期自动判断赛季（8 月起算新赛季）。
- **焦点战**写在 `data/focus.json`（按赛季分组，`date` 用**比赛日期**，不是期次日期），归档页给这些行标 ★ 并高亮。
  - 用 `node scripts/build-focus.mjs` 按规则生成：**BIG6 内战**、**净胜/净负 3 球以上**、**欧战碰强队**（拜仁/皇马/巴萨/尤文/巴黎/米兰/罗马/马竞/多特/莱比锡/阿贾克斯/波尔图/本菲卡/国米/那不勒斯/里昂/比利亚雷亚尔/皇社/毕巴）、**杯赛出局**、**单场 6 球以上**、**赛季最大胜/负**。
  - 同一季同一日期上，手写过的条目**保留手动理由**（脚本只补规则判定），所以「索尔斯克亚首战」这类不会被冲掉。
  - 每季大概 15–35 场（BIG6 一年就 10 场），深写时按 ★ 挑。
  - **纪录只收历史级的**：`data/records-manual.json` 里只写「历史上首次 / 队史里程碑」这种（例：巴黎那场——欧冠淘汰赛史上首支首回合主场 0-2 落败后翻盘的球队）。**赛季内的小纪录一律不写**：补时绝杀、连胜场次、队内射手王、帽子戏法、赛季最快进球都太碎，不配当焦点战。
  - 编辑备注（「索尔斯克亚执教首战」「首回合 0-2 落后」这种语境）放 `data/focus-notes.json`，按 `赛季|比赛日期` 存，脚本拼到理由前面。
- **纯新闻期也占号**：没有比赛的那一期（下课、转正、转会）跟比赛期一起按时间排序编号，和主线第 8 期「赛前·卡里克」一个道理。归档页里这类行赛事写「场外」、比分写「—」。
- **赛季总结单独一期**：放在最后一轮之后（2018/19 是 2019-05-14，第 56 期），内容三块——赛季账本、四条战线、名局，数字由生成器从 archive 和 `data/focus.json` 算，不手抄。有这一期，赛季页就不用再单独做「总结」界面。
  - 配图：把图丢成 `media/season-<slug>-summary.jpg`（如 `media/season-2018-19-summary.jpg`），重跑生成器自动挂上「今日要点」，尺寸自己读，不用手填。
- 归档期次另带 `season`、`archive: true`、`match_no`（当季第几场）。
- **归档只写比分能证明的事**：进球时间线、场地、赛事、截至这一场的累计战绩与连胜连败。没有原话就不写引语，没有同源图就不配图 —— 别拿队徽或别场图凑。
- 判断不越界：累计战绩、赛季最大分差、第几次被零封，一律只算到这一场为止（`tally()` 只取 `slice(0, i+1)`）。
- 杯赛平局按赛制写：联赛杯「九十分钟打平，进入加时；互射点球的结果没有记录」；足总杯「按赛制需要重赛」。不猜结果。
- 球员名保留英文原文（archive 里就是英文），队名、场地走 `scripts/teams-cn.json`。
- 归档期次**不挂积分榜**，期次导航只在本赛季内翻。
- 生成器：`node scripts/gen-archive-issues.mjs 2018-19`（`--all` 全季，`--dry` 只看汇总）。`archive/` 下的页面由它写，别手改。`data/archive/` 由 import 脚本写，生成器只读。

### 淘汰赛路径

- 赛季页顶部一条「淘汰赛路径」：**只画曼联这一条**，不铺整张对阵树。
- 每条赛事一行节点：轮次 → 对手和比分。**比分一律曼联在前**（客场也写 3-1，不写 1-3）。
- 淘汰那一轮的节点标红，并在赛事名旁边挂「止步八强」「点球出局」「夺冠」这种结论；两回合合并写（`0-2 / 3-1`），晋级方式放备注（如「客场进球晋级」）。
- **轮次名来自 ESPN**：`node scripts/build-rounds.mjs <season>` 从 `header.season.name` 取（如「2022-23 English League Cup, Final」），写到 `data/rounds/<season>.json`。生成器优先用它，拿到就按真实轮次聚（小组赛并成一条、两回合并成一条），拿不到才退回「第 N 轮」。
- 结论规则：最后一轮是小组赛/联赛阶段 → 「小组赛出局」；淘汰轮输了 → 「止步X强/第N轮」；**决赛赢了才叫「夺冠」**；打平不能自己判，等手写。
- **点球/加时/重赛这种 archive 里没有**，写进 `data/cup-results.json`（键：赛季 → 赛事 → 结论文案），生成器以它为准。已补两条：
  - 2020/21 欧联 → 「决赛点球负（11-10 比利亚雷亚尔）」
  - 2024/25 足总杯 → 「第五轮点球负富勒姆（3-4）」——顺带记一笔：**2024/25 起足总杯取消重赛**，所以那是点球而不是重赛。
- 小组赛节点写 `group: true`，生成器自己算胜平负和积分。

### 欧战小组表

- 紧跟「淘汰赛路径」下面，**只放曼联所在那一组**，4 行，曼联行标红。
- 数据：`node scripts/fetch-group.mjs 2018-19 champions|europa` 从 ESPN 抽出来，写到 `data/groups/<season>.json`；生成器读它。换赛季先跑一次这个脚本。
- 不写「小组第几出线」这类结论——排名表本身已经说明，结论交给淘汰赛路径那一行。

## 视角

- **当天视角**，不用上帝视角。写 10 月 11 日的稿子，不知道后面九场不胜。
- 只写当天已经知道的事：当时的排名、当时的伤情、当时说过的话。
- **禁止跨期判断**，这类句式一律不写：
  - ❌「从那到现在一共九场没赢」→ ✅「六轮 1 胜 3 平 2 负，第 13」
  - ❌「此后一直没有回到一线队训练」→ ✅「上半场拉伤，被提前换下」
  - ❌「此后一个月没有出场」→ ✅「在比赛里伤到髋部，被换下」
  - ❌「这是九场不胜里最难看的一场」→ ✅「这是本赛季丢球最多的一场」
  - 判据：写这句话的时候，作者当时**能不能知道**。
- 例外：数据面板可以写"截至目前"。

## 点评

- 侧栏 `note.body` 一句话，写**判断**不写复述。一期只用一条。
- **排版约定**：引别人的原话**自动加「」**（页面按 `credit` 是否存在来加，数据里不用手写引号）；下面一行只要**破折号 + 球迷名**（`—— 众人皆醉唯我独醒丶`），名字链回原帖。**不写赞数**，简约一点更好看。自己写的那句两样都不加。
- 来源二选一：
  - **懂球帝热评**：`note.title` = 「懂球帝热评」，必须带 `credit`（网友名 + 赞数）和 `url`（原文链接），页面渲染成署名引评。
  - **自己写的**：`note.title` = 「编辑短评」，不署名，按下面编辑的标准。
- **不是每条都得引热评。**热评写得好就搬原话，写得不好或者没有就自己写：
  - 「好」的判据：视角对、能**独立看懂**（不靠上下文补话）、有一句判断或情绪、不是纯刷屏梗、长度像一句话。
  - 搬就**搬原话**：可以删减、补标点，别润色成编辑腔——改着改着两头不讨好。
  - 找不到合格的（比如最高赞全是对面的嘲讽），直接自己写，不硬凑。
- **视角必须站曼联（或中立）**。对手球迷的嘲讽、幸灾乐祸、「感谢曼联送温暖」一律不用，哪怕赞数最高。
  - 判据：把这句话贴到曼联球迷群里，大家会点头还是会被惹火。
  - 赢球时优先「自家人的激动/自嘲」，输球时优先「冷静的自省」或中立的技战术评价。
  - 例：「全世界最他妈有血性的球队」——带脏字，但替曼联说话，**可以用**；「感谢曼联送温暖」——没脏字，但是对面口气，**不能用**。
- **热评不套编辑那套冷静标准**：口语、感叹号、喊口号都可以，那股劲正是热评的价值。但**人身攻击、地域黑、性侮辱、攻击球员或家属**一律不用，骂得再准、赞再高也不用。
- **自己写的那句**：冷静、具体、不喊口号。反例「球队需要反思」；正例「主场 0-3，这一个月里最像失控的一场」。
- 热评怎么取：懂球帝文章页评论区（`dl.comm > dd`，登录后可见），按赞数排序**逐条看视角和措辞**再定，不是直接拿第一条。
- 两种页面别混：
  - **战报页** `m.dongqiudi.com/zhanbao/<id>` —— 有进球时间、首发、技术统计，**写稿时拿来核对事实**，但没有评论区。
  - **新闻文章** `m.dongqiudi.com/article/<id>.html` —— **标题带比分的那种才热闹**，热评只在这里；`zhanbao` 和一部分 article 一条评论都没有，取之前先确认。

## 特稿与配图

- 人工内容写进 `scripts/featured/<season>.json`，不要手改生成出来的 `data/seasons/*`。
- 三种能力：`note`（热评/点评覆盖）、`items[]`（追加条目，如格林伍德首秀）、`hero`/`images`（配图）。
- 日期键用**期次的 date**（赛后次日），不是比赛日。

## 引语

- 用**发布会/采访原文**，不转述。
- 三段式：`zh`（中文一句）/ `en`（英文原话）/ `who` + `when`。
- 中文可以有取舍，但**不能改变原意**；英文保留口语，不修饰。

## 图片

- **不裁切**，按原比例，单张 `max-height: 380px`，组图 `max-height: 240px` 并排。
- 图要和新闻**同源**：看台抗议配看台，别配球员合影。
- 比赛图来自曼联官网战报页（版权属曼联 / Getty），仅个人使用，不公开分发。
- **归档期次**：每期一张头图（「今日要点」左边那张），正文里只有**重要的条目**才配图。
  - 头图来源：`node scripts/fetch-archive-images.mjs <season>` 从 ESPN 的 summary 接口取该场的 `article.images[0]`（署名多在 Getty），存 `media/archive/`，索引 `data/images-<season>.json`，生成器自动挂上。
  - **别抓 `news.articles[*]`**——那是 ESPN 的推荐位，图跟这场比赛无关（我踩过：53 场下回来只有 9 张不重复的，全错）。
  - 覆盖情况：9 季 447 场里 416 场有图，缺的那些 ESPN 本身就没配图（2020/21 缺 6、2021/22 缺 5、2022/23 缺 9）。

## 球队与队徽

- 队徽一律用 **FM 的 small 小图（25×18 PNG）**，页面按原尺寸显示，别缩放、别裁。
- FM 编号不用去论坛查：**kits 包的 config.xml 里就有**。`graphics/kits/FC'12 Season 202324/<联赛文件夹>/config.xml` 每行是
  `<record from="cardiff1" to="graphics/pictures/team/625/kits/home"/>` —— 前半是球队 slug，后半的数字就是 FM unique ID。
  遍历所有联赛文件夹就能得到一张 slug → 编号表（这批 4337 支）。
- 注意 slug 会撞：`barcelona` 同时有厄瓜多尔一支和西甲一支，**要连联赛文件夹一起看**（西甲的是 1708）。巴黎的 slug 是 `paris_sg`（868），不是 `paris`（867，巴黎 FC）。
- **kits 包里没有的队，去 `fmtransferupdate.com` 查最快**：站内搜索队名，页面右上角直接写 `ID: 708`（谢菲尔德联）这类，有时还带国家（`Futbol Klub Astana / Kazakhstan · ID 59041139`）。备选是 `https://www.fmscout.com/club/<slug>.html?rev=24.0`，编号藏在队徽地址里（`geniescout.com/logos/clubs/1687.png` → 1687），但它的 slug 缩写没规律（马竞是 `a-madrid`），拼不出来就别硬猜。
- 查到编号后到 FM 的 logos 目录按 `<编号>.png` 找那支队的图，拷进 `media/badges/`。
- 队徽 25×18，页面按原尺寸显示，别缩放、别裁。
- 积分榜数据以**懂球帝**为准（`node scripts/fetch-boards.mjs`），ESPN 只作交叉核对或应急回退。
- 榜单一律 20 行、曼联行标红；归档期次不挂榜单（见「归档」）。
- 归档的对手队徽走 `scripts/teams-cn.json`（英文名 → 中文名 / badge / fm）。三件缺一，条目就少徽标或显示英文名。

## 来源分级

| 级别 | 用途 |
|---|---|
| 曼联官网 / 官方发布会全文 | **事实基准**：比分、阵容、伤情、原话 |
| BBC / Sky / 曼晚 / 泰晤士 | 可信分析、独家 |
| 懂球帝 / 直播吧 / 虎扑 | 找线索、中文表述；**多为转载，不直接用结论** |
| X（跟队记者、罗马诺） | 转会突发；**必须标"未证实"** |

- 每条都要带 `sources`，链接指向**原文**，不指向聚合页。
- 官方没发声的事，写"尚无官方声明"，不要替它下结论。

## 排版

- 一页一个 `h1`。正文列宽 38em。字号只允许四档。
- 组件不写裸像素和裸颜色，一律走 CSS 变量。
- 主题跟内容走：早报白纸，晚报近黑。**不跟系统深色设置走**。
- 顶栏的「版本切换（日更/周报/单场/杂志）」已删掉——现在只跑日报一种编法，`data-weekly` / `data-deep` / `data-magazine` 是早期对比用的，随时能删。

## 发布（2026-11-13 起：不打发布包）

- **仓库根目录就是站点**，GitHub Pages 直接从这个分支的根目录出页。改完直接 commit + push，没有中间产物、没有 `_site`。
- 提交前跑 `node scripts/check-size.mjs`：超过预算 200 MB、或有单个 >200 KB 的文件会报出来。
- `.gitignore` 挡住了 `tmp/`、`_site/`、`*.bak`、以及早期的 `data-weekly` / `data-deep` / `data-magazine`——用 `git add -A` 前确认一下，别把中间产物带进去。
- 图片按赛季放 `media/archive/<赛季>/`，一季 40–60 张、4–6 MB；网页上传时先打开 `media/archive/` 目录页再拖赛季文件夹，否则会套成两层。
- 本地预览：`启动.cmd`（带 no-cache 的 serve.py），或 `python serve.py`。
- 线上：https://silverherring1.github.io/manutd-daily/
